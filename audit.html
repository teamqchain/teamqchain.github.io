Internal Security Audit

Where QChain Is Strong,
and Where It Isn't Yet

A full-stack security audit of the QChain post-quantum credential system (backend, chaincode, Fabric network, gateway, database and client apps) mapped to the six classical security properties.

Reviewed: 2026-08-08 Post-G2 codebase

Verdict at a glance

  • ☞Cryptographic core is solid. ML-DSA-44 signing, SHA3-256 integrity, and the new Track B/G2 encryption are correctly built and verified.
  • ☞Access control is the weak point. The API has no authentication and one shared identity.
  • ☞Two logic gaps bite verification: expired credentials still pass, and OTP codes are brute-forceable.
  • ☞Identity layer is still classical. Fabric MSP/TLS remain ECDSA.

Executive Summary

QChain does the hard cryptography well: the credential signature, hashing, and off-chain/on-chain confidentiality are post-quantum and correctly implemented. The risks that remain are conventional application-security gaps (authentication, input validation, key custody and operational hardening) plus the deliberately-deferred post-quantum identity work. None of the criticals are cryptographic; all are fixable without new research.

Scope & Methodology

A manual source-code review of the QChain repository at the post-G2 state, covering the Go backend, JavaScript chaincode, Fabric network configuration, the Nginx gateway, database schema and the Flutter clients. Findings are classified by severity (impact × exploitability) and mapped to the six classical security properties. The cryptographic implementation was reviewed by tracing the actual code paths, not the documentation, and the Track B/G2 primitives were compiled and unit-tested with real ML-KEM.

In scope

  • Go backend (offchain/) - API, crypto, DB, Fabric client
  • Chaincode (qchain-network/chaincode/QChaincode.js)
  • Network config: core.yaml, configtx, docker-compose, fabric-ca
  • Web gateway (Nginx) and enrolment/setup scripts
  • MySQL schema & migrations; Flutter client trust model

Severity model

Critical - trivially exploitable, high impact (e.g. forge/revoke any credential)
High - serious impact or clear attack path
Medium - needs conditions, or defence-in-depth gap
Low - hygiene, hardening, minor issues
Strength - implemented correctly / defends well

What the System Gets Right

Prioritised Remediation Roadmap

Ordered by value ÷ effort. The first tier removes the critical and the two verification-logic gaps (none require new research and all can be done in the backend).

TIER 1: NOW

Close the exploitable gaps

  • Add API authentication (JWT/session) + per-role authorization on every privileged route; lock CORS to known origins. (F01)
  • Enforce expiry at verification - treat expiryDate < now as not-valid, and/or a status-sweep job. (F02)
  • Rate-limit + lock out OTP/resolveSession; consider 8-digit or alphanumeric tokens. (F03)
  • Add a request body-size limit (http.MaxBytesReader). (F10)
TIER 2: SOON

Harden keys, secrets & ops

  • Move signing + KEM keys off .env to a KMS/HSM; separate custody. (F06, F16)
  • Rotate all default credentials (CouchDB, fabric-ca admin:adminpw). (F09)
  • Encrypt PII columns (Track C) reusing the Track B envelope. (F11)
  • Make the mobile-session redemption atomic (mark-used in one UPDATE). (F12)
  • Anchor/sign audit logs; pin Docker images; add gateway security headers + rate-limiting. (F13, F14, F15)
TIER 3: RESEARCH

Post-quantum identity & resilience

  • Replace ECDSA in the Fabric MSP/TLS with ML-DSA (see the Track A implementation plan). (F04)
  • Holder-held keys + signed presentations; real cryptographic selective disclosure. (F08, F17)
  • Multi-orderer/peer, second IPFS node, DB replication for availability. (F18)

Context: this is a research capstone, not production

Several findings (single-VM topology, open demo access, default demo credentials) are acceptable for a supervised university demo and are called out for honesty in any write-up rather than as blockers. The Tier 1 items, however, undercut the system's own security claims even in a demo and should be fixed first.
