Comprehensive Security Audit

Where QChain Is Strong,
and Where It Isn't Yet

A rigorous source-code security audit of the QChain post-quantum credential system (Go backend, Hyperledger Fabric chaincode, network configuration, web gateway, MySQL schema, and Flutter clients) mapped to the six classical security properties.

Reviewed: 2026-10-25 Track H / Current Codebase 4 Key Vulnerabilities Resolved

Verdict at a glance

  • ☞Cryptographic core is post-quantum and robust. ML-DSA-44 issuance signatures, holder presentation signatures, cryptographic selective disclosure with salted field commitments, and ML-KEM-768 envelope encryption are verified.
  • ☞Major verification gaps resolved. Credential expiry enforcement, cryptographic selective disclosure, holder presentation signing, and fail-fast IPFS validation have been successfully implemented.
  • ☞Access control & API hygiene remain critical. A newly added test cleanup route (/dev/cleanupTest) enables unauthenticated data wiping, and public key registration allows potential key hijacking.
  • ☞Identity layer is still classical. Fabric node MSP X.509 certs, consensus signatures, and gRPC TLS remain classical ECDSA (Track A research scope).

Executive Summary

QChain has made substantial architectural strides since the initial August 2026 assessment: four major vulnerabilities have been fully resolved, including on-chain expiry enforcement, true cryptographic selective disclosure via salted commitments, and holder presentation signing with post-quantum ML-DSA-44. However, conventional web-service authorization remains the critical attack surface: unauthenticated endpoints allow administrative actions, demographic enumeration, and arbitrary database record wiping. None of these vulnerabilities stem from cryptographic weaknesses; all are remediable with standard application-security patterns.

Scope & Methodology

A line-by-line manual source-code audit covering the Go backend (offchain/), JavaScript chaincode (QChaincode.js), network configuration (Fabric, Docker, CA), Nginx web gateway, MySQL schema, and Flutter clients (UI_App & UI_WebApp). Every finding is evaluated against actual code execution paths, unit tests, and threat models rather than architectural documentation.

Audited Surface

  • Go API & Crypto Engine (offchain/): Handlers, commitment builder, KEM/DEM envelope, verification logic, and DB drivers.
  • Smart Contract (qchain-network/chaincode/QChaincode.js): Lifecycle, access control checks, and deterministic state storage.
  • Network & Orchestration: Docker compose, Fabric CA configurations, and bootstrap scripts.
  • Web Gateway & Client Trust Models: Nginx configuration, Tailscale Funnel ingress, and mobile Flutter secure hardware storage.

Prioritised Remediation Roadmap

Ordered by risk reduction vs. engineering effort. Tier 1 tackles newly identified exploitable routes and core authentication.

TIER 1: IMMEDIATE

Eliminate critical data-loss & authentication holes

  • Remove or strictly guard POST /dev/cleanupTest: Ensure test cleanup code cannot run in production or without root credentials. (F21)
  • Lock down bindHolderKeys: Enforce one-time immutable key binding in chaincode and verify holder identity before registering public keys. (F22)
  • Introduce API Authentication: Add JWT / session middleware and role-based access control (RBAC) across all privileged routes; restrict CORS. (F01)
  • Rate-limit & Lockout Verification Tokens: Add attempt counters and IP rate limiting on /resolveSession; consider alphanumeric presentation tokens. (F03)
  • Protect Demographic Endpoints: Require authentication for /mobile/getHolderProfile, /mobile/checkKeys, and /getHolders. (F23, F24)
TIER 2: SHORT-TERM

Key custody, concurrency & operational hardening

  • Protect Org Signing Key: Migrate ISSUER_PRIVATE_KEY_HEX from plaintext .env to an HSM or cloud KMS (PKCS#11). (F06)
  • Atomic Session Redemption: Enforce atomic mark-and-delete on mobile_sessions to eliminate token replay race conditions. (F12)
  • Request Body Caps: Wrap request bodies in http.MaxBytesReader across all API handlers to prevent memory exhaustion DoS. (F10)
  • Credential Hygiene: Rotate default credentials for CouchDB and Fabric CA bootstrap identities. (F09)
  • Gateway Hardening & PII Encryption: Add HSTS, CSP, and rate limiting in Nginx; apply Track C field encryption to MySQL PII columns. (F07, F14)
TIER 3: STRATEGIC

Quantum-safe identity & high availability

  • Track A Implementation: Replace ECDSA in Fabric BCCSP, peer MSP certificates, and TLS with ML-DSA for end-to-end quantum resistance. (F04)
  • High Availability Topology: Deploy multi-consenter Raft ordering, redundant peer nodes across distinct availability zones, an IPFS cluster, and high-availability MySQL replication. (F18)
  • Blockchain Audit Checkpoints: Cryptographically anchor off-chain operational audit logs to ledger state. (F13)

Context & Transparency Statement: this is a research capstone, not production ready

QChain is a cutting-edge post-quantum applied research blockchain based credential management system. Demonstrating academic honesty by publishing this comprehensive internal audit reinforces credibility: while the core post-quantum credential architecture, envelope cryptography, and holder-signed presentations are robustly implemented, addressing conventional access control and operational hygiene remains essential before production readiness.
