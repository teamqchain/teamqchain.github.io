Audit Verdict at a Glance

  • ■ Cryptographic core is post-quantum and robust: ML-DSA-44 issuance signatures, holder presentation proofs, cryptographic selective disclosure with salted field commitments, and ML-KEM-768 envelope encryption are mathematically sound.
  • ✓ Key vulnerabilities resolved: Expiry enforcement, cryptographic selective disclosure, holder presentation signing, and fail-fast IPFS validation are implemented and passing tests.
  • ! Conventional API authentication remains open: Privileged routes require JWT / session authentication middleware, rate limiting, and CORS lockdown before production readiness.

Executive Summary

QChain has made significant architectural strides: four major vulnerabilities have been resolved, including on-chain expiry enforcement, true cryptographic selective disclosure via salted commitments, and holder presentation signing with ML-DSA-44. Conventional web-service authorization remains the critical attack surface—none of these flaws stem from cryptographic weaknesses; all are remediable with standard application-security patterns.

Prioritized Remediation Roadmap

Sequenced by risk reduction versus engineering effort to guide immediate hardening.

TIER 1: IMMEDIATE

Eliminate critical authentication holes & unauthenticated cleanup

  • Remove POST /dev/cleanupTest: Ensure test cleanup code is removed from the production router. (F21)
  • Lock down bindHolderKeys: Reject public key overwrites once keys are registered. (F22)
  • Introduce API Authentication: Add JWT middleware and role-based access control (RBAC) across all privileged routes. (F01)
  • Rate-Limit & Lockout OTP Tokens: Add IP rate limiting on /resolveSession. (F03)
  • Protect Demographic Endpoints: Require authenticated staff sessions for holder lookups. (F23, F24)
TIER 2: SHORT-TERM

Key custody, concurrency & operational hardening

  • Protect Org Signing Key: Migrate ISSUER_PRIVATE_KEY_HEX from plaintext .env to an HSM or cloud KMS (PKCS#11). (F06)
  • Atomic Session Redemption: Enforce atomic mark-and-delete on mobile_sessions to eliminate token replay race conditions. (F12)
  • Request Body Caps: Wrap request bodies in http.MaxBytesReader to prevent memory exhaustion DoS. (F10)
  • Gateway Hardening & PII Encryption: Add HSTS, CSP, and rate limiting in Nginx; apply Track C field encryption to MySQL columns. (F07, F14)
TIER 3: STRATEGIC

End-to-end quantum-safe identity & high availability

  • Track A Implementation: Replace ECDSA in Fabric BCCSP, peer MSP certificates, and TLS with ML-DSA for end-to-end quantum resistance. (F04)
  • High Availability Topology: Deploy multi-consenter Raft ordering, redundant peers, and an IPFS cluster. (F18)
  • Blockchain Audit Checkpoints: Cryptographically anchor off-chain operational audit logs to ledger state. (F13)

Transparency & Research Integrity Statement

Publishing this comprehensive internal source-code audit reinforces credibility and transparency: while the core post-quantum credential architecture, envelope cryptography, and holder-signed presentations are robustly implemented, addressing conventional access control and operational hygiene remains essential before enterprise production readiness.
